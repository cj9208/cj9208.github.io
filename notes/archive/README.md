# notes/archive — 讨论过但决定不写的选题

留档「已经认真讨论过、结论是不值得单独成文」的选题，避免同一件事隔几个月又被当成新想法重新讨论一遍。

与 `notes/blog-todo.md` 的分工：

- `blog-todo.md` = 要写的
- `notes/archive/` = 决定不写的，以及**不写的理由和残差去了哪里**

## 收录标准

一个选题进 archive，通常是因为它落在这两类里：

1. **纯验证性案例**：真实事件只是确认了站内已发布的机制，信息增益接近零。按惯例应作为标本/附注并入原文，而不是新写一篇。
2. **机制未越界**：事件用到的底层机制，站内已有文章声明的适用域已经覆盖。

判定用的问题是：**这个案例有没有把某个机制推到它自己声明的适用域之外？**

- 有 → 值得写（新文章或原文的实质性新章节）
- 没有 → 归档，并把可复用的部分拆成附注并入原文

站内反复出现的底层机制大致就这么几个，新事件多半只是换参数：

- 责任与收益错配（谁拿溢价谁兜底）
- 裁判席空缺或被俘获
- 纸面合规替代实质问责
- 高维介入引发反向解码（塔西佗陷阱）
- 信息控制触发史翠珊效应

## 文件写法

- 文件名：`YYYY-MM-DD-<主题>.md`，日期是讨论发生的日期
- 每篇记录四段，都要短：
  1. **事件**：时间线只留判断所依赖的事实，标注单一来源项
  2. **判断与逻辑链**：当时的看法，以及事后被修正的部分
  3. **残差**：哪些组件站内已写过（给出文章 slug 与章节），哪些是真新的
  4. **处置**：决定了什么——并入哪篇的哪一节、还是彻底放弃、以及放弃的理由

第 3 段是这个目录的主要价值。它记的是「已经想过什么」，下次同一话题出现时先看这里，再决定要不要重开。
