# 记得住，删不掉：Agent 长期记忆的六个问题与九个流派，与为什么治理轴是唯一的承重点

> 主线一句话：**所有叫"AI 记忆"的东西回答的都是同一个问题——下一次推理应该被哪些过去塑造；分歧只在表征、控制者、时机、治理四个轴上。前三轴 2023→2026 有清晰迁移（规则→自编辑→可学习策略；写入时→后台巩固；明文→试图下沉权重），第四轴基本没动：测过的六套主流系统无一通过 >1.5% 的删除请求。于是路线之争的实质不是"要不要记忆"，而是"记忆该不该是一个可独立审计、可独立删除、可独立问责的子系统"。**

## 一、结论：记忆不是存储问题，是写策略问题

分歧落在四个轴上：

| 轴 | 取值 | 说明 |
|---|---|---|
| **表征** | 外部明文 / 上下文内 / 激活潜空间 / 权重参数 | 记忆"住在哪里" |
| **控制者** | harness 启发式规则 / 模型自编辑 / 训练出的策略 | 谁决定写什么、读什么 |
| **时机** | 写入时（在线） / 后台巩固（sleep-time） / 读取时 | 什么时候花算力整理 |
| **治理** | 无 / 时间衰减 / 失效标记 / 版本化 / provenance | 能不能删、能不能审、能不能回滚 |

2023→2026 的演化在这张表上是三条可指认的迁移：

1. **控制者**从规则（recency×importance×relevance 三因子）→ 模型自编辑（MemGPT 的函数调用改上下文）→ **可学习策略**（MemAgent、Mem-α、AgeMem 用 RL 学"何时生成什么记忆"）。
2. **时机**从"写入时抽取"→ **后台巩固**（sleep-time compute、dreaming、离线递归整合）。
3. **表征**在外部明文上稳固了三年，2026 年开始尝试**下沉回权重**（Titans/Atlas 测试时记忆；记忆张量 2026-10-20 开源 MemT-1.0 系列，288B/36B、激活 17B/3B，把可更新内部记忆纳入模型计算【二手，新华财经】）。

而第四轴**治理**基本没动：测过的六套主流记忆系统，无一通过 >1.5% 的删除请求（Bemula，arXiv:2610.18052【二手】）。这是全篇最重要的一条空白，也是金融场景真正的阻断点。

## 二、问题树：六个问题，每个问题各自的解法与代价

不按项目罗列，按"它试图解决什么问题"分。每个问题给：问题 → 为什么这么解 → 用什么技术 → 现在的证据。

### P1 容量：上下文窗口有限，且会话关掉即失忆

**为什么这么解**：窗口是稀缺资源，与其扩大窗口不如把它当 RAM 调度——这是 OS 隐喻的全部正当性。把"记什么"变成模型自己的函数调用，记忆管理就进了推理循环，而不是外挂一个 RAG 插件。

**技术**：MemGPT（arXiv:2310.08560【一手】，2023-10）LLM=CPU、窗口=RAM、外存=磁盘，分页 + 自编辑上下文；产品化为 Letta（Core/Recall/Archival 三层 + memory blocks，Apache 2.0）。后续把记忆升级为**资源与治理对象**：MemoryOS（arXiv:2506.06326【二手】）短/中/长期 + 热度分页；MemOS（arXiv:2507.03724【二手】）把明文/激活/参数三种 MemCube 当一等资源调度。⚠️ 同名坑：另一篇 Memos（2505.22101）是不同团队。

**证据**：这一族的优势是白盒可控，代价是重（需 server + Postgres）；对"30 分钟就结束的 chatbot"ROI 为负【二手，多家横评一致】。

### P2 召回：跨会话把"当时说过的事实"找回来

**为什么这么解**：最朴素的判断——把对话抽成原子事实存起来，用时检索。便宜、通用、不依赖特定 harness。

**技术**：向量库 + LLM 抽取（mem0，arXiv:2504.19413【一手】称结构化抽取在 LoCoMo 胜过全上下文）；关联索引走图——HippoRAG（arXiv:2405.14831【一手】）无 schema KG 作海马索引 + Personalized PageRank，**单步检索内完成多跳**；HippoRAG 2「From RAG to Memory」（arXiv:2502.14802【一手】）补的是"图化之后事实记忆反而变差"这个短板；A-MEM（arXiv:2502.12110【一手】）用 Zettelkasten 原子笔记 + 动态链接，让新记忆**回溯改写**旧记忆的标签——这一句直接打破了 MemGPT/MemoryBank 的"只增不改"。

**证据（反证，最重要）**：2026-10《Is Complex Agentic Memory Always Needed? Naive RAG Is Stronger Than We Thought》（arXiv:2610.30755【一手，本轮点开确认】）——Raw-RAG 在 LoCoMo/LongMemEval/MEME/MemoryAgentBench 的**七个 setting 中六项第一**，超最强 agentic memory 系统 0.13–5.53 分。同向结论另有 2608.12888、2601.00821【二手】。即：**P2 上复杂记忆系统的收益至今没有被中立证明过。**

### P3 时间性：不是"事实是什么"，而是"当时是什么状态"

**为什么这么解**：向量库里的事实没有时间维度，矛盾靠 LLM 现场判。要回答"上季度这条规则是什么"，必须把有效期做成一等公民。

**技术**：Zep/Graphiti（arXiv:2501.13956【二手】）双时态图，episode/entity/edge 带 `valid_at`/`invalid_at`，**失效不删除**，可溯源；检索为向量 + BM25 + 图遍历，**查询期不调 LLM**（延迟与成本可控，也意味着行为可复现）。Cognee（ECL 流水线 → 图 + 向量 + 关系三元存储）。

**证据**：这是唯一能答"当时是什么"的一族，代价是图 DB 运维（Neo4j/FalkorDB）+ 抽取成本 + pre-1.0 成熟度（graphiti-core 0.31.2）。**Zep 社区版已于 2025-04-02 官方弃维护**【一手，仓库状态】，`getzep/zep` 现仅剩示例与集成，自托管实际只有 Graphiti 库 + 图库；完整 Zep 仅云/BYOC。

### P4 经验：从"记起"到"学会"

**为什么这么解**：召回只解决信息，不解决能力。要让 agent 第二次做得比第一次好，得把轨迹提炼成可复用的程序性知识，并给它一个离线整理的时机。

**技术**：
- 认知类型学落地——概念源头 CoALA（arXiv:2309.02427），Generative Agents（arXiv:2304.03442【一手】）memory stream + recency/importance/relevance 三因子 + reflection 提炼高层洞察，Reflexion（arXiv:2303.11366【一手】）言语化反思写入 episodic buffer（无梯度更新）。工程上最完整的是 **MIRIX**（arXiv:2507.07957【一手，本轮点开确认】）：Core / Episodic / Semantic / Procedural / Resource / Knowledge Vault **六类记忆** + 多智能体协调器动态控制更新与检索；Memp（2508.06433）专做程序记忆。
- 时机轴的后台巩固——Sleep-time Compute（arXiv:2504.13171【一手】，Letta/Berkeley）空闲期离线重推断重写记忆，测试时算力最高省 5×；CMU/UMD 离线递归记忆整合（arXiv:2605.26099【二手，编号经转述确认】）N 轮循环前向更新 SSM 快权重；Anthropic 2026-05 宣布 "dreaming" 记忆整理研究预览【二手】；Letta 2026-06 研究博客《Memory Models: Towards Agents That Learn》提出 memory-native RL【一手，官方博客】。
- 控制者变成可学习对象——MemAgent（2507.02259，固定长度覆写 + 多对话 RL）、Mem-α（2509.25911，RL 学记忆建构）、AgeMem（arXiv:2601.01885，ACL 2026，把 LTM/STM 操作当工具动作交给 agent 自主决策 + 渐进式 RL）、Mem-π（2605.21463，学"何时生成什么记忆"以替代检索）、MemEvolve（2512.18746，进化架构本身）【均为二手，编号待核】。
- 参数侧——Titans（arXiv:2501.00663【一手，本轮核过；常被误写成 2501.07537】）测试时梯度更新神经长期记忆，**surprise 决定记、权重衰减决定忘**；Atlas（2505.23735）；Larimar（2403.11901）分布式情景记忆做 one-shot 知识更新。

**证据（含一条反直觉主张，未核验勿引）**：有计算学论文主张记忆巩固的本质**不是防灾难性遗忘，而是离线跨领域重组以产生单域不可能的新能力**【二手，仅见 Zhihu 推介，未读到原文】。这条若成立会改写 P4 的论证结构，落笔前必须找到原论文。

### P5 遗忘与治理：该忘的忘不掉

**为什么这个问题重要**：遗忘不是清理，是**正确性**问题。临时假设、被推翻的方案一旦被永久化，会成为后续所有步骤的前提；而"有损记忆比空记忆更糟"已有实名论文（arXiv:2606.25449【二手】）。

**技术与现状**：MemoryBank（2305.10250）最早引 Ebbinghaus 遗忘曲线；2026 转向治理视角——FSFM 选择性遗忘（2604.20300）、TRUSTMEM 可信巩固（2606.25161）、图式化选择性遗忘（2608.28978）、Governed Memory（2603.17787）【均二手】。工程实现里**真做**衰减/矛盾的只有三家：MemoryOS（时间衰减 + 配额）、Graphiti（失效标记）、Hindsight（冲突版本化 + `proof_count` 佐证 + token budget）；其余靠 LLM 现场判。

**证据（本族最刺眼）**：
- Bemula（arXiv:2610.18052【二手】）：6 套主流记忆系统**无一通过 >1.5% 的删除请求**。
- ForgetEval（2606.15903【二手】）：生产失败主要是**遗忘失败**而非召回失败。
- 软撤销默认不执行（2609.08258）；删掉文本后图片仍可恢复（2606.29788）；派生摘要残留约 20% 可恢复（2606.10062）【均二手】。
- 记忆已更新但行为未更新：STALE 的 IPA gap（2608.01619）；信念/观点漂移 BeliefShift（2603.23848）；记忆演化安全 MemEvoBench（2604.15774）结论是**静态 prompt 防御不足**【均二手】。

### P6 安全与合规：记忆同时是攻击面和责任面

**为什么**：写入通道是新的、持久的、且跨会话生效的——这正好是提示注入最想要的属性。

**技术/证据**：
- 治理层已把它列为独立条目：**OWASP Agentic Top 10 (2026) 的 ASI06 "Memory & Context Poisoning"**【一手，genai.owasp.org】。
- 学术源头 AgentPoison（arXiv:2407.12784【一手】）；2026 细分出潜伏式 Sleeper Memory Poisoning（2605.15338）、多条无害记忆合谋的"香肠"攻击（2608.01637）、工具劫持（2605.26154）、跨会话存储注入（2606.04425）、以及**无攻击者的自我传播错位**（2610.04083，结论：只做审计或干脆关掉记忆都不够）【均二手】。缓解共识：来源绑定 + 机器可验证权限（2606.24322）、写期自一致准入（2607.22962）、检测基准 MemSecBench（2607.27080）。
- 厂商侧真实 PoC：Rehberger 2024-09 / 2025-02 的 ChatGPT 与 Gemini 记忆持久注入；Tenable 2025-11 报 ChatGPT 记忆注入（OpenAI 修复中）【二手】。**没有一起生产环境被真实利用的公开事故报告**——只有 PoC 与修补。
- 多租户泄漏（对银行最致命）：共享向量库的**非对抗**跨用户语义泄漏 70–100%，端到端污染 5/5，且**被污染的回答被人类判为"更有帮助"**；只有硬 ownership gating 能恢复干净基线，代价 +~1.4ms/query（arXiv:2610.04195【二手】）。
- 合规：**没有找到任何一份监管文件明确点名 "agent memory"**【本轮检索结论】。MAS《Guidelines on AI Risk Management》2026-10-07 发布、2027-10-07 起分阶段生效（数据治理、测试评估、人工监督、可解释性、变更管理、第三方 AI 责任不外包、AI 台账），且把 agentic AI 专项指引推到 **2027 年才咨询**【二手，联合早报】。EU 侧有 2604.04604、2603.23471，Art.12 日志可审计性见 2610.07459。工程上的审计抓手是三件现成的事：事务边界（2607.27834）、版本控制与语义回滚（2607.27773）、provenance（2605.30771）。

### 补充线：共享记忆作为多智能体协作层（2026 才成形）

G-Memory（arXiv:2506.07398，NeurIPS 2025，三层图记协作经验）、计算机架构视角的缓存/一致性分层（2603.10062）、Agentsensus 共识压缩共享记忆（2609.32297）【均二手】。这条线与 P3/P5 共用技术栈，但目标函数不同：它优化的是**多个 agent 对同一事实的一致视图**，本质是分布式一致性问题被搬进了记忆层。

## 四、路线之争：目前没有共识

| 立场 | 主张原文 | 论据 | 反证 |
|---|---|---|---|
| **外部检索派**（需要独立记忆子系统） | Mem0 论文 arXiv:2504.19413【一手】 | 结构化抽取在 LoCoMo 上胜过全上下文 | arXiv:2610.30755【一手】Raw-RAG 七个 setting 六项第一，超最强 agentic memory 0.13–5.53 分 |

**本调研的判断**：分歧的实质不是"要不要记忆"，而是"**记忆该不该是一个可独立审计、可独立删除、可独立问责的子系统**"。上下文工程派在 P1/P2 上很可能已经够用（RAW-RAG 是强证据），但它在 P5/P6 上结构性无解——明文散落在上下文与文件里，删除请求无处落地。这是判断银行场景该走哪条路的那把尺。

### 为什么这些数字不可信（都有实名证据，非泛泛而谈）

1. **厂商互测撕破脸，至今无中立复现**：Mem0 复现 Zep 得 **58.44%** vs Zep 自称 **84%**（[getzep/zep-papers#5](https://github.com/getzep/zep-papers/issues/5)【一手，公开 issue】），Zep 回击《Lies, Damn Lies, and Statistics》称对方配置错误。裁判模型、top_k、检索粒度、是否含对抗题四类配置各家不同。
2. **换掉裁判，分数普遍掉 15–22 点**：LoCoMo-Refined（南大 + 上海 AI Lab，2026-04，[repo](https://github.com/mem-eval-suite/LoCoMo_refined)，1382 题）报旧裁判 GPT-4o-mini 在人工精标集上准确率仅 **43.67%**，新裁判 86.33%；重测 Mem0 **48.91%** / MemOS 63.60% / MemPalace 58.68% / EverMemOS 58.25%。⚠️ **该工作只有 GitHub + 媒体稿，无 arXiv、未经同行评审**，分数取自其 README，未经第三方复现【未核验】。另有 [Penfield Labs 审计](https://penfieldlabs.substack.com/p/we-audited-locomo-64-of-the-answer)称 1540 题中答案键本身 **6.4% 是错的**【二手】。
3. **方法论缺陷有实名论文**：静态快照不随规模退化（2605.07313）；judge 只判相关性、需 source-aware grading（2610.05343）；有损记忆比空记忆更糟（2606.25449）。
4. **成本/延迟长期缺席**：MERIT（2609.05441）是少数把 token 与美元同时计量的；Mem0 vs 长上下文成本模型（2603.04814）给出临界点——**100K 上下文下约 10 轮之后记忆系统才更便宜**【均二手】。
5. **端到端准确率被当成"记忆能力"**：检索层被大 top_k 或全量上下文绕过时，测的其实是阅读理解。
6. **攻击成功率被理想化**：MINJA 自称 >95% 注入成功率 / 70% ASR，论文自述是**理想条件**；2601.05504 显示有既存合法记忆时攻击效果"大幅降低"【二手】。

### 本轮未能证实、不应被当作事实的说法

- 题为《Are They Really Better?》的 LoCoMo 再评估论文：**arXiv 检索无此篇**（其论点由 2610.30755 / LoCoMo-Refined 覆盖）。
- 针对 LoCoMo/LongMemEval 的**预训练污染定量测量**：未找到专门论文（只有通用污染方法学，如 2407.08716、2310.18018）。

- 同名双论文需分辨：MemAgent（2507.02259 vs 2609.32521）、MemOS/Memos（2507.03724 vs 2505.22101）。

## 六、银行场景的落地判断

三条硬约束，每条都对应上面的一个证据：

1. **删除必须真的生效。** Bemula 测的六套系统无一通过 >1.5% 的删除请求，派生摘要残留约 20% 可恢复，删文本后图片仍可恢复。→ 选型的第一道门槛不是召回率，是"给定一条 PII，能否证明它及其派生物已不可恢复"。目前只有 Graphiti 的失效标记与 Hindsight 的版本化提供了可审计的机制雏形。
2. **多租户必须硬隔离，不能靠语义边界。** 非对抗条件下跨用户语义泄漏 70–100%，且污染回答被人类判为"更有帮助"（意味着人工抽检抓不到）。硬 ownership gating 的代价只有 +~1.4ms/query——**这是全场性价比最高的一个决定**。
3. **"记住了"不等于"照着做"。** MERIT：正确取到值后只有 55% 真的据此行动；STALE 的 IPA gap 说明记忆更新与行为更新之间存在系统性落差。→ 风控/合规问答不能只验检索命中率，必须验**行为一致性**，且写入是异步最终一致的（Zep 论文自己承认"隔几小时再查显著更好"），不能假设"客户刚说的这句话立刻可检索"。

采购侧的四件事：**"开源"标签 ≠ 引擎开源**（Supermemory 的 MIT 只覆盖客户端；Zep 完整平台仅云；OpenViking/Honcho 是 AGPL；Memori/memU 许可证元数据 NOASSERTION）；**默认都调外部 LLM 做抽取**，这既是成本点也是数据出域点，需切本地模型；**隐性依赖**（Graphiti 需 Neo4j/FalkorDB，Cognee/Hindsight 需 PG+pgvector，Letta 需 server+DB）；**成熟度**（graphiti-core 0.31、langmem 0.0.30、多数仍 pre-1.0）。

如果今天要落一个最小可用方案，按"确定性优先、额外行为最少"的口径，我的排序是：**文件即记忆（可 git diff、可审计、零依赖）作主干 + Graphiti 式双时态图作时间性补充 + 自建离线评测集**，而不是先引入一个自报 SOTA 的黑箱记忆服务。理由见 §四那把尺：只有独立子系统能承载删除权与问责，而独立子系统里只有带有效期的表征能回答"当时是什么"。

### 6.1 本机 n=1 实测（2026-10-27，Qoder auto memory）

§一—§五全是文献。这一节是本机自测：样本 n=1、单机、单 harness，但**可重跑**，是全篇唯一一处一手数据。

被测系统：Qoder auto memory——索引 `MEMORY.md` 每次会话全量注入，主题文件按需读（渐进披露；与 Claude Code Auto Memory 同构，后者启动加载 `MEMORY.md` 前 200 行/25KB）。

**(a) 注入成本——确定的年金**

- 记忆索引：用户级 ~2.2k + 项目级 ~0.6k ≈ **2.85k token/会话**（估算口径：CJK 字符 ≈1 token、其余 ≈3.5 字符/token；**非实测账单**）
- 另有 `agents.md` ~3.6k token/会话，属项目指令，不计入记忆
- 换算（按 Anthropic 公开定价推算：cache read $0.30/MTok vs input $3/MTok）：每万次会话 **~$8.55（静态前缀可缓存）vs ~$85.5（动态内容不可缓存）**，差约 10×
- 重跑：统计三个文件的字符数即可；价格随厂商调整需重算

**(b) 命中率——12 个会话样本（2026-10-23 ~ 10-26），分母 49 条索引条目**

| 观测 | 结果 |
|---|---|
| 样本窗口内主题从未出现 | **14 / 49（28.6%）** |
| 主题相关 | 35 条，其中约 8 条仅弱相关 |
| **硬命中**（显式读取或引用主题文件） | 12 个会话仅 **1 次** |
| 行为符合某条规则 | ≥7 例，但**不可归因** |
| **负命中**（已注入却在当轮被违反） | 1 例清晰 |

高频条目确实存在（最高 5/12 个会话），所以结论不是"记忆无用"，而是**分布极不均**——而索引对全部 49 条一视同仁地每次注入。那个负命中与 §五 SWE-Skills-Bench 的 39/49 零改善同形：**注入不保证遵守**。

限制：主题覆盖率 ≠ 因果命中率。"符合规则"的行为无法排除基线（多数规则本就是通用良好实践）。要测因果需三条件配对重跑（注入 / 不注入 / 注入无关索引），本轮未做。

**(c) 索引一致性——写入与索引之间存在以小时/天计的异步窗口**

- 22:44 首测：用户级 **40 个主题文件 vs 索引 38 条** → 2 个孤儿；项目级 12 vs 11 → 1 个孤儿。孤儿 = 主题文件已写入但索引里没有它，因此**永不注入、事实上不存在**
- 22:50:42 两个索引被系统整体重写，复测 **40/40、12/12，孤儿与死链均归零**
- 用文件 mtime 量窗口：用户级两个孤儿写于 2026-10-26 10:06:13 → 窗口 **36 小时 44 分**；项目级那个写于 2026-10-11 14:04:20 → 窗口 **16 天 8 小时**
- 成因：主题文件写入与索引更新不是同一事务；补齐只在索引被整体重写时发生（本次由本会话的记忆写入触发），**没有独立的对账机制**
- 重跑：取 `MEMORY.md` 中 `](xxx.md)` 链接集合与磁盘 `*.md` 集合的双向差集；窗口长度需配合 mtime 才算得出来

> 【更正 2026-10-27 22:52】本节初稿写的是"2/40 = 5% 静默丢失"，把它当成了持久状态。首测约 6 分钟后索引自愈、孤儿归零，所以正确表述是**异步窗口**而非永久丢失。但窗口长度以小时到天计（36h / 16d），比 §六 硬约束 3 里 Zep 自己承认的"隔几小时再查显著更好"还要长一个量级——原判断的严重程度不变，机制说法作废。保留此块，不静默覆盖。

**这次自愈顺带产出了本轮唯一一次因果证据。** 那两个孤儿文件恰好是 `feedback-measurements-need-unit-and-rerun`（数字要写单位/口径/可重跑命令）与 `feedback-mechanism-over-documentation`（能被静默违反的规则要配检测器）。它们不在索引里的那 36 小时，执行本次测量的 agent **不知道这两条规则存在**——所以 (c) 的初稿写出了"5%"这种无单位、无口径、无重跑命令的断言。22:50:42 索引补齐、规则注入后，同一 agent 在约 6 分钟内把该节改写成带 mtime、带估算口径、带重跑命令、带【更正】块的形式。

这是 (b) 里唯一能排除基线的一次观测：**同一执行者、同一任务、间隔约 6 分钟，唯一差别是规则在不在索引里**。两点推论：

1. 孤儿不是无害冗余，而是**行为差异**。
2. 这种差异**不可自检**——缺了规则的那次输出看起来完全正常，只有事后对比才暴露。这也意味着 (b) 的"硬命中 12 个会话仅 1 次"可能被系统性低估：当命中的表现形式是"避免了一个本来会犯的错误"时，它在单次观察里根本不可见。

**(f) 附带：索引由系统整体重写，人工更正不留痕**

22:36 我手工改写过项目级索引里那条 bullet（把过期断言改成实际状态并注明更正时间）。22:50:42 的系统重写把它**替换成了自动生成的摘要**——过期断言消失了（好事），但我的更正说明与日期也一并消失（坏事）。主题文件里的手工更正段落**存活**，未被重写。

含义：这套记忆的修订模型是**覆盖，不是修正**。对照本仓库 `docs/decisions/` 的约定（采纳后不重写正文；被推翻时新增一篇写"取代 000N"，旧篇只加一行状态行），差别正好落在审计链上——覆盖式修订让"这条曾经错过、什么时候改的、谁改的"无法追溯。这是 6.2 治理最小集里"失效标记而非删除"要解决的问题，在个人 agent 的记忆层上同样成立。

**这五组观测对上文的用处**：(b)+(c) 说明注入是全量确定的、使用是稀疏的、且写入与索引之间有 36 小时到 16 天的窗口；(d) 给出了 Bemula"六套系统无一通过 >1.5% 删除请求"的**机制解释**——副本分散在 harness 各层，删除 API 只覆盖记忆层；(a) 给出了下面 6.2 两半的成本分岔量级。同时它给"文件即记忆"一个公允评价：**残留是可 grep 枚举的**（本次就是靠 grep 找到的），向量库里连有哪些副本都不知道——但**可发现 ≠ 可删除**。

### 6.2 方案骨架：personalized profile + shared knowledge

上面那个排序（文件即记忆作主干）内部还要再切一刀，因为两半的**成本结构**与**治理义务**都不同。

**profile（个人画像）= 静态、槽位化、钉在前缀。**

它在治理轴上实质更优，理由比"更简单"硬：槽位化把删除从**语义问题降级为 SQL 问题**（UPDATE/DELETE，语义确定，没有自由文本抽取那种派生残留）；冲突可判定为 last-write-wins——而 §五那条讽刺性证据正好说，一个冻结的 last-write-wins 解析器在 MemoryAgentBench 的 selective forgetting 上答对 80.25%。**受限表征下最笨的策略就够用**；自由文本记忆之所以需要复杂机制，是它自己制造出来的问题。成本上它落在 (a) 的便宜档（静态前缀可缓存），所以**可以厚**。附带好处：schema 化让"条目存在但未加载"变成可判定状态，对照 (c) 那 5% 静默丢失。

**长尾：不是换存储，是换生命周期。**

纯 schema 只能记"已经想到要记"的东西，长尾恰恰是"还不知道该建哪个槽位"。解法是两层——一层廉价、append-only 的自由文本**捕获层**，明确标注为临时且不具权威性；经**晋升**进入 schema 层。**治理义务附着在晋升边界上，不附着在捕获上**：临时层里错了、过期了、删不干净，代价有限；一旦晋升，就要承担可删除、可审计、可问责的全部义务。同构物就在本仓库——`notes/` 是捕获层（不受 front matter / lastmod / 公开链接约束），`content/` 是晋升层（全套发布规则），**晋升边界即治理边界**。

两条纪律：

1. **晋升判据 = 频率 OR 不可逆性，不能只用命中率。** 只用 (b) 的覆盖率会误杀保险型条目。本站实例：`date/lastmod` 晚于系统时钟 → 整站静默构建失败（一年触发一次，一次即致命）；中文文件名编码损坏不可逆。这类低频高代价条目必须常驻。
2. **自动晋升目前没有证据支撑。** Auto-RecSys 三路分流中，前两路（自然语言运维知识、固定 schema 状态）判据对且有数字，第三路（自由文本 lessons）违反自己的判据且零数字；本机 `notes/reading/dream-rsi-replay-simulator-notes.md` §5.1 的负结果（"+Guidance 蒸馏进 prompt 稳定更差"）是它的一个实例。→ 长尾靠人肉或半自动晋升；**sleep-time compute / dreaming 那条线不要放在晋升这一步上**。

**shared knowledge（组织共享知识）= 动态检索、多写者、按次付费。**

成本上它落在 (a) 的贵档（每次检索内容不同 → 缓存不了 → ~10×）。设计含义：能不进上下文就不进，进则压到最小高信号集合——即 Anthropic 那句原话。风险面上，共享 = 多写者，ASI06 的全部威力在此释放；且**被污染的回答被人类判为"更有帮助"**，意味着人审会系统性放过污染，所以门禁必须机械化。

治理最小集五件事，以及本仓库已有的同构约定：

| 治理要件 | 证据/出处 | 本仓库现有同构物 |
|---|---|---|
| provenance + as-of 必填 | 2605.30771【二手】 | `docs/research/` 固定头部（as-of + 失效条件） |
| **不可重跑的断言不入库** | 同上 | "手抄的计数不可重跑，等于没有标签" |
| 冲突用失效标记而非删除 | Graphiti `valid_at`/`invalid_at` | `docs/decisions/` 不重写正文；新增一篇写"取代 000N"，旧篇只加状态行 |
| 查重，防同一话题反复重开 | — | `search-blog-articles` + `notes/archive/`（决定不写的也记下来） |
| 定期事实审计 | MAS 变更管理（2027-10-07 生效）【二手】 | `0002` 待办最后一条：半年一次事实审计 |

按"能被静默违反的规则要配检测器"这把尺量一下，上表五行在本仓库**目前的机制化程度并不均等**：只有第 3 行有真机制——Hugo 遇到晚于系统时钟的 `date/lastmod` 会构建失败或静默丢页，违反即有后果；第 1、2、4、5 行都是 **documentation-only**，靠人（或 agent）自觉执行，可以被静默违反且不会报错。

(c)+(f) 两组观测正好是这个缺口的后果：一个没有对账机制的记忆层，会同时出现"写了没被加载"（36 小时—16 天窗口）与"改了不留痕"（覆盖式重写），两者都不报错。

→ 所以落地顺序是**先给这五行各配一个检测器，再谈让 agent 执行**。检测器都很便宜：(c) 的双向差集扫描是十行脚本；provenance/as-of 缺失可以用 front matter 校验；查重已有现成的 `search-blog-articles`；"不可重跑的断言不入库"可以用"是否附重跑命令"做机械检查。**这套体系不需要发明，需要的是先从"写下来"变成"能被检测"，然后才是从人肉执行变成 agent 执行。**

**明确标为未解决的缺口**：profile 记"这个人是谁"，shared knowledge 记"这个组织知道什么"，中间的 **P4 程序性经验**（轨迹级、带失败样本）两半都不覆盖——它不属于个人画像（是任务级的），也不属于组织知识（提炼成结论本身就是一次有损压缩）。务实处理：先不做，或明确标为实验，不要假装被前两半覆盖了。
