AI CHIEF OF STAFF

Prompt Playbook

AI CoS Capstone and Professional Expertise

**Purpose.** This is the participant-facing task layer. Project
Instructions define how the AI behaves; the Codified Professional
Expertise Handbook provides professional judgement; What Good Looks Like
defines the output standard. The prompts below simply tell the AI what
to do now.

+----------------------------------------------------------------------+
| HOW TO USE THIS PLAYBOOK                                             |
|                                                                      |
| Do not paste this whole playbook into Project Instructions. Copy     |
| only the prompt that matches the task you are doing. When moving to  |
| a new conversation, carry forward an explicit handoff rather than    |
| assuming the AI will reconstruct the previous reasoning.             |
+----------------------------------------------------------------------+

# Quick map

  **Situation**                                            **Use**
  -------------------------------------------------------- ---------------------------------------------------
  I have 2-3 possible opportunities                        Prompt 1 - Compare candidate opportunities
  I have selected a provisional direction                  Prompt 2 - Deepen the selected opportunity
  I need to go back into the organisation this week        Prompt 3 - Plan fieldwork and socialisation
  I have stakeholder notes or evidence                     Prompt 4 - Debrief reality and update the project
  I need a clean capstone framing                          Prompt 5 - Create or update the project framing
  I am changing conversations or tools                     Prompt 6 - Create a handoff note
  I need expertise I do not already have                   Prompt 7 - Create a Deep Research brief
  I am ready to run Deep Research                          Prompt 8 - Reconstruct professional expertise
  I have research and need a durable guide                 Prompt 9 - Turn research into codified expertise
  I want to test whether the codification is good enough   Prompt 10 - Audit the codification

PART A

Capstone workflow prompts

Use these prompts to move from candidate opportunities to evidence,
organisational movement and a strong project framing.

# 1. Compare candidate opportunities

**When to use:** Use when you have two or three plausible opportunities
and need to choose a provisional direction without converging too early.

+----------------------------------------------------------------------+
| OUTPUT / HANDOFF                                                     |
|                                                                      |
| End with a compact handoff note. That handoff becomes the starting   |
| context for Prompt 2.                                                |
+----------------------------------------------------------------------+

+----------------------------------------------------------------------+
| COPY / PASTE PROMPT                                                  |
|                                                                      |
| I have the following candidate organisational transformation         |
| opportunities:                                                       |
|                                                                      |
| IDEA A: \[PASTE\]                                                    |
|                                                                      |
| IDEA B: \[PASTE\]                                                    |
|                                                                      |
| \[IDEA C, if relevant: PASTE\]                                       |
|                                                                      |
| Use the Codified Professional Expertise Handbook and What Good Looks |
| Like as references. Your role is to coach me through a fair          |
| comparison, not to choose too early.                                 |
|                                                                      |
| First help me clarify each opportunity enough to compare it          |
| properly. Ask one focused question at a time where useful. Do not    |
| invent facts about my organisation.                                  |
|                                                                      |
| For each opportunity, help me understand the organisational outcome, |
| current reality, who benefits, why it matters, potential value,      |
| transformation potential, the role of AI if any, what AI genuinely   |
| changes, my sphere of influence, access to evidence and              |
| stakeholders, important constraints, assumptions, unknowns and       |
| warning signs.                                                       |
|                                                                      |
| Challenge weak framing. In particular, challenge me if an idea       |
| starts with a technology, is justified because another organisation  |
| is doing it, relies on vague claims such as efficiency or            |
| productivity, fixes the solution before the problem is understood,   |
| or simply automates an inherited process without questioning it.     |
|                                                                      |
| Once the ideas are sufficiently clear, help me compare them. Do not  |
| use a simplistic scoring model. Surface the important trade-offs,    |
| including importance versus influence, ambition versus tractability, |
| demonstrability versus depth, and speed versus confidence.           |
| Distinguish what is evidenced from what is assumed.                  |
|                                                                      |
| Help me reach a provisional decision that I own. End with a handoff  |
| note containing: the provisional direction; why I currently prefer   |
| it; the strongest evidence; important assumptions; important         |
| unknowns; what could change my mind; and the next validation         |
| questions.                                                           |
+----------------------------------------------------------------------+

# 2. Deepen the selected opportunity

**When to use:** Use after you have selected a provisional project and
need to understand the larger transformation properly before defining
the near-term advance.

+----------------------------------------------------------------------+
| OUTPUT / HANDOFF                                                     |
|                                                                      |
| The output should be a Capstone Working Brief, not a polished final  |
| proposal.                                                            |
+----------------------------------------------------------------------+

+----------------------------------------------------------------------+
| COPY / PASTE PROMPT                                                  |
|                                                                      |
| I have provisionally selected the following organisational           |
| transformation opportunity:                                          |
|                                                                      |
| \[PASTE THE HANDOFF NOTE FROM THE COMPARISON\]                       |
|                                                                      |
| Use the Codified Professional Expertise Handbook as reference. Coach |
| me to deepen the opportunity before we move into detailed solution   |
| design.                                                              |
|                                                                      |
| Do not discuss the four-week advance until the larger transformation |
| is clear enough.                                                     |
|                                                                      |
| Help me clarify what the organisation is fundamentally trying to     |
| achieve; what happens today; why the current situation exists; who   |
| is involved and affected; where value, friction, delay, risk, wasted |
| capacity or missed opportunity arise; what evidence supports the     |
| problem; whether I am seeing the root problem or a symptom; and what |
| assumptions I am making.                                             |
|                                                                      |
| Then challenge the current system. Help me explore whether the work  |
| should be improved, redesigned or reinvented. Ask what would be      |
| different if today\'s AI capabilities had always existed. Do not     |
| force AI into the answer. Clarify what AI could materially change    |
| and what should remain human-led or non-AI.                          |
|                                                                      |
| Also explore the organisational conditions that could change the     |
| judgement: stakeholder incentives, ownership, access, data,          |
| governance, risk, adoption, dependencies and my realistic ability to |
| create movement. Ask rather than infer when context is missing.      |
|                                                                      |
| Once the larger transformation is sufficiently clear, ask: \"What    |
| would most materially advance this larger project in the next four   |
| weeks?\" Then help me determine what I would need to show, prove,    |
| validate, learn, unlock or get decided to achieve that advance.      |
|                                                                      |
| The four-week advance should be organisational progress, not a       |
| technical milestone by default. It may be evidence, validation,      |
| stakeholder learning, access, sponsorship, a redesigned process, a   |
| decision, a test, a prototype or another concrete change in the      |
| state of the project.                                                |
|                                                                      |
| End with a Capstone Working Brief containing: the opportunity;       |
| current reality; desired outcome; larger transformation; role of AI  |
| if relevant; potential value; evidence currently available;          |
| assumptions and unknowns; organisational conditions; four-week       |
| advance; evidence of progress; and the next questions to validate.   |
+----------------------------------------------------------------------+

# 3. Plan fieldwork and socialisation

**When to use:** Use before the between-weekend fieldwork. The goal is
contact with reality and organisational movement, not a large homework
exercise.

+----------------------------------------------------------------------+
| OUTPUT / HANDOFF                                                     |
|                                                                      |
| Aim for one or two high-quality interactions rather than activity    |
| for its own sake.                                                    |
+----------------------------------------------------------------------+

+----------------------------------------------------------------------+
| COPY / PASTE PROMPT                                                  |
|                                                                      |
| Use my current Capstone Working Brief below to help me plan a small  |
| fieldwork sprint inside my organisation.                             |
|                                                                      |
| \[PASTE WORKING BRIEF\]                                              |
|                                                                      |
| The purpose of the fieldwork is twofold: first, to test reality and  |
| improve my understanding of the opportunity; second, to begin        |
| socialising the work and create useful organisational movement. It   |
| is not to sell a finished AI solution.                               |
|                                                                      |
| Help me identify the one to three assumptions or unknowns that       |
| matter most right now. Then help me choose the most useful           |
| evidence-gathering method for each: a stakeholder or user discovery  |
| conversation, observation or shadowing, a data check, document or    |
| process review, a small survey, an expert conversation, external     |
| research or a bounded experiment.                                    |
|                                                                      |
| Prioritise people I can realistically access and who can credibly    |
| challenge the framing. For each conversation, help me define what I  |
| need to learn and what organisational movement would be useful:      |
| awareness, challenge, an introduction, access to data, permission to |
| test, interest, sponsorship or another concrete next step.           |
|                                                                      |
| Prepare discovery questions that focus on actual reality and past    |
| behaviour. Prefer questions such as \"Walk me through the last time  |
| this happened\" or \"What happens when this goes wrong?\" Avoid      |
| leading questions such as \"Would you use an AI tool that does X?\"  |
|                                                                      |
| Also help me frame the outreach credibly. I am participating in an   |
| intensive AI transformation programme and using a real               |
| organisational opportunity as the vehicle for the work. I want to    |
| use that legitimacy without pretending I already have the answer.    |
| Draft a short outreach message that says I am exploring the area,    |
| gathering evidence and would value the person\'s perspective.        |
|                                                                      |
| End with a lightweight fieldwork plan containing: the objective; the |
| person or evidence source; the assumption being tested; the key      |
| questions; what evidence I will capture; the socialisation or        |
| influence objective; and the next useful ask.                        |
+----------------------------------------------------------------------+

# 4. Debrief reality and update the project

**When to use:** Use after interviews, observation, data gathering,
surveys, expert conversations or small experiments.

+----------------------------------------------------------------------+
| OUTPUT / HANDOFF                                                     |
|                                                                      |
| A successful debrief should be able to name at least one meaningful  |
| change in the thinking or in the organisation.                       |
+----------------------------------------------------------------------+

+----------------------------------------------------------------------+
| COPY / PASTE PROMPT                                                  |
|                                                                      |
| I have completed fieldwork on my capstone. I will paste my notes,    |
| observations, data or stakeholder feedback below.                    |
|                                                                      |
| \[PASTE FIELDWORK EVIDENCE\]                                         |
|                                                                      |
| Use the Codified Professional Expertise Handbook to help me          |
| interpret what I learned. Do not protect my original idea from       |
| contrary evidence.                                                   |
|                                                                      |
| First separate the material into: direct evidence or observed facts; |
| stakeholder statements; my interpretation; assumptions;              |
| contradictions; and new unknowns. Flag where the evidence is weak or |
| ambiguous.                                                           |
|                                                                      |
| Then compare what I believed before the fieldwork with what I now    |
| know. Help me identify what was strengthened, weakened, disproved,   |
| reframed or made more important. Ask what surprised me and what      |
| evidence should change the project.                                  |
|                                                                      |
| Also examine organisational movement. Who now understands the        |
| opportunity? Who challenged it? Did I gain an introduction, access,  |
| data, permission, interest, sponsorship or another useful            |
| commitment? Did I discover a blocker, incentive or political reality |
| that changes how the project should move?                            |
|                                                                      |
| Use the new evidence to update the larger transformation and, if     |
| necessary, the four-week advance. Do not keep the existing framing   |
| merely for consistency.                                              |
|                                                                      |
| End with: (1) an updated Capstone Working Brief; (2) a short         |
| fieldwork evidence summary stating what changed because of contact   |
| with reality; and (3) the next most important uncertainty, person,   |
| evidence or organisational action.                                   |
+----------------------------------------------------------------------+

# 5. Create or update the project framing

**When to use:** Use when you need a coherent capstone artefact from the
current evidence. It can be used repeatedly as the project evolves.

+----------------------------------------------------------------------+
| OUTPUT / HANDOFF                                                     |
|                                                                      |
| The project framing should evolve when evidence changes. A cleaner   |
| document is not a substitute for better evidence.                    |
+----------------------------------------------------------------------+

+----------------------------------------------------------------------+
| COPY / PASTE PROMPT                                                  |
|                                                                      |
| Use the Codified Professional Expertise Handbook and the What Good   |
| Looks Like document as references.                                   |
|                                                                      |
| Here is my latest Capstone Working Brief and fieldwork evidence:     |
|                                                                      |
| \[PASTE LATEST MATERIAL\]                                            |
|                                                                      |
| Create or update my capstone project framing. Do not introduce any   |
| organisation-specific fact that is not supported by the material I   |
| provided. If a critical fact is missing, ask me before drafting or   |
| mark it explicitly as unknown or to validate.                        |
|                                                                      |
| Write in clear, specific, professional prose. Do not make the        |
| document framework-heavy or turn it into a checklist. The            |
| opportunity should be understandable to a senior person who has not  |
| followed the previous conversations.                                 |
|                                                                      |
| Structure the framing around:                                        |
|                                                                      |
| \- The opportunity: a concise narrative explaining the current       |
| situation, why it matters, the transformation that may be worth      |
| pursuing and the potential impact.                                   |
|                                                                      |
| \- Current reality: what happens today and what evidence supports    |
| that understanding.                                                  |
|                                                                      |
| \- Desired outcome: what should be better, for whom and why.         |
|                                                                      |
| \- The larger transformation: the meaningful organisational change,  |
| which may extend well beyond the programme.                          |
|                                                                      |
| \- Role of AI: what AI materially enables, if anything, without      |
| making AI the project by definition.                                 |
|                                                                      |
| \- Potential value: the value hypothesis, quantified where           |
| reasonably possible and explicit about assumptions.                  |
|                                                                      |
| \- Key assumptions and unknowns: what still needs to be established  |
| and what could change the framing.                                   |
|                                                                      |
| \- The four-week advance: the most valuable progress that can        |
| materially increase the likelihood that the larger transformation    |
| succeeds.                                                            |
|                                                                      |
| \- Evidence of progress: what will show that the project has         |
| genuinely moved forward.                                             |
|                                                                      |
| \- Organisational movement: relevant stakeholders, what has been     |
| socialised or unlocked, and the next useful ask where appropriate.   |
|                                                                      |
| Use What Good Looks Like as the quality bar, not as text to copy     |
| mechanically. Preserve uncertainty where it is real.                 |
+----------------------------------------------------------------------+

# 6. Create a handoff note

**When to use:** Use whenever you move between chats, projects, tools or
models. This is the explicit context bridge.

+----------------------------------------------------------------------+
| COPY / PASTE PROMPT                                                  |
|                                                                      |
| Before we stop this conversation, create a handoff note for the next |
| conversation or AI tool.                                             |
|                                                                      |
| Use only information established in this conversation. Do not add    |
| new facts or recommendations.                                        |
|                                                                      |
| Include:                                                             |
|                                                                      |
| 1\. Current project framing and larger transformation.               |
|                                                                      |
| 2\. Decisions made and the reasoning behind them.                    |
|                                                                      |
| 3\. Important facts or evidence.                                     |
|                                                                      |
| 4\. Assumptions and inferences.                                      |
|                                                                      |
| 5\. Unknowns and what still needs validation.                        |
|                                                                      |
| 6\. What changed during this conversation.                           |
|                                                                      |
| 7\. Current four-week advance and evidence of progress, if defined.  |
|                                                                      |
| 8\. Stakeholder or organisational movement so far.                   |
|                                                                      |
| 9\. The exact next task I should continue with.                      |
|                                                                      |
| Make it compact enough to paste at the start of a new conversation,  |
| but complete enough that the next AI does not have to reconstruct    |
| the reasoning from memory.                                           |

PART B

Professional expertise prompts

Use these only when you are creating or rebuilding the expertise layer
itself. They are not needed every time you work on the capstone.

+----------------------------------------------------------------------+
| IMPORTANT DISTINCTION                                                |
|                                                                      |
| Deep Research here is upstream. Its purpose is to reconstruct        |
| professional expertise when you do not already have enough of it. It |
| is not primarily a way to research your specific capstone idea.      |
+----------------------------------------------------------------------+

# 7. Create a Deep Research brief

**When to use:** Use when you know you need expertise, but the research
question itself is still vague.

+----------------------------------------------------------------------+
| COPY / PASTE PROMPT                                                  |
|                                                                      |
| I need to use Deep Research to reconstruct professional expertise    |
| for a judgement or task that I do not know well.                     |
|                                                                      |
| Do not research yet. First help me formulate the research brief.     |
|                                                                      |
| Ask me one question at a time, and only ask what is necessary to     |
| understand:                                                          |
|                                                                      |
| \- the professional judgement or task I need expertise for;          |
|                                                                      |
| \- who normally makes this judgement;                                |
|                                                                      |
| \- the professional or organisational context in which it occurs;    |
|                                                                      |
| \- what a good outcome looks like;                                   |
|                                                                      |
| \- what expertise or source material I already have;                 |
|                                                                      |
| \- any important source, industry, geography or recency constraints. |
|                                                                      |
| Challenge me if I describe only a broad topic rather than a          |
| professional judgement. For example, \"AI transformation\" is a      |
| topic; \"How do experienced transformation leaders identify and      |
| select organisational transformation opportunities worth pursuing?\" |
| is a professional judgement.                                         |
|                                                                      |
| Once the judgement is clear, produce a copy-paste Deep Research      |
| prompt. The research brief should ask how excellent practitioners    |
| make the judgement, not ask the researcher to solve my specific      |
| case. It should investigate objectives, questions, criteria,         |
| reasoning sequence, trade-offs, heuristics, warning signs, novice    |
| mistakes, evidence, context dependencies, disagreements and          |
| examples. It should require strong source provenance and distinguish |
| established findings, practitioner heuristics, disagreement and      |
| synthesis.                                                           |
|                                                                      |
| End only with the completed Deep Research prompt.                    |
+----------------------------------------------------------------------+

# 8. Reconstruct professional expertise with Deep Research

**When to use:** Use when the professional judgement is clear and you
need a rich source base before codifying it.

+----------------------------------------------------------------------+
| OUTPUT / HANDOFF                                                     |
|                                                                      |
| The output of Deep Research is still information about expertise. It |
| is not automatically the finished codification.                      |
+----------------------------------------------------------------------+

+----------------------------------------------------------------------+
| COPY / PASTE PROMPT                                                  |
|                                                                      |
| Deep Research Task: Reconstructing Professional Expertise            |
|                                                                      |
| I want you to conduct deep research into the professional expertise  |
| involved in making the following judgement well:                     |
|                                                                      |
| \[INSERT PROFESSIONAL JUDGEMENT OR TASK\]                            |
|                                                                      |
| The purpose of this research is to create a rich information base    |
| that can later be converted into a durable Professional Expertise    |
| Guide for an AI system. This is not research into my specific        |
| project and I do not want a recommendation for my particular         |
| situation.                                                           |
|                                                                      |
| Investigate how highly experienced practitioners actually make this  |
| judgement. I want to reconstruct the professional reasoning          |
| underneath frameworks and checklists: what strong practitioners      |
| notice, what they try to understand first, what makes them           |
| interested or sceptical, what evidence changes their confidence,     |
| what assumptions they challenge, what trade-offs they make and what  |
| causes them to reframe or stop.                                      |
|                                                                      |
| Research across high-quality sources. Prioritise experienced         |
| practitioners speaking from direct practice; authoritative           |
| professional organisations; detailed case studies; documented        |
| failures and post-mortems; established frameworks where they         |
| genuinely illuminate practice; and academic research where it        |
| materially improves understanding of professional judgement. Do not  |
| over-weight generic SEO articles, superficial \"steps\" lists or     |
| vendor marketing. Where possible, trace popular claims back to       |
| original or primary sources and look for contradictory evidence      |
| rather than only consensus.                                          |
|                                                                      |
| Specifically investigate:                                            |
|                                                                      |
| 1\. What excellent practitioners are ultimately trying to achieve.   |
|                                                                      |
| 2\. The questions they ask before making the judgement.              |
|                                                                      |
| 3\. The factors and criteria they consider.                          |
|                                                                      |
| 4\. The sequence in which they tend to think.                        |
|                                                                      |
| 5\. Important trade-offs and tensions.                               |
|                                                                      |
| 6\. Heuristics and rules of thumb.                                   |
|                                                                      |
| 7\. Warning signs and recurring failure modes.                       |
|                                                                      |
| 8\. Assumptions inexperienced practitioners often make.              |
|                                                                      |
| 9\. What evidence experts seek before becoming more confident.       |
|                                                                      |
| 10\. How they distinguish known facts, assumptions, inference and    |
| uncertainty.                                                         |
|                                                                      |
| 11\. How they decide which uncertainty is most important to          |
| investigate next.                                                    |
|                                                                      |
| 12\. Situations where context materially changes the answer.         |
|                                                                      |
| 13\. Areas where credible experts disagree.                          |
|                                                                      |
| 14\. Examples that reveal how an expert thought, not merely what     |
| they did.                                                            |
|                                                                      |
| 15\. Cases where a superficially attractive approach failed, and     |
| what the failure teaches about judgement.                            |
|                                                                      |
| Do not simply produce a literature review or a source-by-source      |
| summary. Synthesize the material into coherent professional insight. |
|                                                                      |
| Produce three layers of output.                                      |
|                                                                      |
| PART I - INFORMATION ABOUT THE EXPERTISE                             |
|                                                                      |
| Write a substantial synthesis explaining what the evidence shows     |
| about how experienced practitioners make this judgement. Include     |
| convergence, nuance, trade-offs, failure patterns, disagreement,     |
| contextual dependencies and examples. This section is allowed to be  |
| rich and discursive because its purpose is to preserve the source    |
| material and reasoning that will later be codified.                  |
|                                                                      |
| PART II - CANDIDATE CODIFIED EXPERTISE                               |
|                                                                      |
| Extract candidate principles, reasoning patterns, conditional        |
| decision rules, diagnostic questions, evidence requirements, warning |
| signs, common novice mistakes, context dependencies, trade-offs,     |
| examples of strong and weak reasoning, and quality standards. Do not |
| reduce the material to slogans. Where possible, express conditional  |
| judgement: if X is true, what should an experienced practitioner     |
| become more or less concerned about, what should they ask next, and  |
| what evidence would change the judgement?                            |
|                                                                      |
| Clearly distinguish:                                                 |
|                                                                      |
| \- strongly supported principles;                                    |
|                                                                      |
| \- useful practitioner heuristics;                                   |
|                                                                      |
| \- areas of genuine disagreement;                                    |
|                                                                      |
| \- your own synthesis or inference.                                  |
|                                                                      |
| PART III - PROFESSIONAL EXPERTISE GUIDE SPECIFICATION                |
|                                                                      |
| Propose the structure of a standalone Professional Expertise Guide   |
| that could be given to an AI system as durable reference context.    |
| The guide should help an AI ask better questions and challenge a     |
| professional\'s thinking without pretending it knows                 |
| situation-specific facts that it has not been given.                 |
|                                                                      |
| Throughout the research, cite substantive claims, prefer primary and |
| authoritative sources, distinguish evidence from interpretation,     |
| flag common but weakly evidenced claims, and preserve genuine        |
| uncertainty rather than manufacturing consensus.                     |
|                                                                      |
| Final quality test: if I gave the resulting material to a powerful   |
| AI model, would it merely know more about the topic, or would it     |
| have enough reconstructed professional judgement to challenge a      |
| practitioner more intelligently? If the answer is only the former,   |
| deepen the analysis before finalising.                               |

# 9. Turn research into codified expertise

**When to use:** Use after you have a sufficiently rich information base
and want to create the durable professional handbook.

+----------------------------------------------------------------------+
| OUTPUT / HANDOFF                                                     |
|                                                                      |
| The substantive handbook should teach the judgement in prose. A      |
| quick-reference checklist can exist at the end, but it is not the    |
| codification itself.                                                 |
+----------------------------------------------------------------------+

+----------------------------------------------------------------------+
| COPY / PASTE PROMPT                                                  |
|                                                                      |
| Using the research and practitioner material below, create a         |
| Professional Expertise Guide for:                                    |
|                                                                      |
| \[INSERT PROFESSIONAL JUDGEMENT OR TASK\]                            |
|                                                                      |
| \[PASTE OR ATTACH THE RESEARCH / SOURCE MATERIAL\]                   |
|                                                                      |
| This guide will be used as durable reference context by an AI that   |
| acts as a professional thinking partner. Its purpose is to codify    |
| how a strong practitioner thinks, not merely to summarise what       |
| experts say.                                                         |
|                                                                      |
| Write the main guide as a professional handbook, predominantly in    |
| coherent prose. Do not turn the expertise into a long bullet list, a |
| framework poster or a simplistic checklist. Professional judgement   |
| lives in the relationships between principles, context, evidence,    |
| exceptions and trade-offs, so explain those relationships.           |
|                                                                      |
| Begin by defining the professional judgement and the scope of the    |
| guide. Then explain what excellent judgement looks like and the      |
| reasoning journey a strong practitioner tends to follow. Develop the |
| major areas of expertise in depth.                                   |
|                                                                      |
| For each important principle or area of judgement, make the          |
| professional reasoning operational. Explain why it matters, how an   |
| experienced practitioner interprets different situations, what       |
| conditional rules or heuristics they use, what questions they ask,   |
| what evidence increases or decreases confidence, what warning signs  |
| trigger concern, what inexperienced people commonly misunderstand,   |
| what trade-offs are involved, what contextual factors can change the |
| judgement and where reasonable practitioners may disagree.           |
|                                                                      |
| Use examples of weak, intermediate and strong reasoning to make the  |
| expertise concrete. Explain why the stronger reasoning is better; do |
| not merely rewrite it more elegantly.                                |
|                                                                      |
| Preserve uncertainty and context dependence. Explicitly identify     |
| facts that an AI could never know from the guide alone and therefore |
| must ask the user about. Do not imply that a generic guide can       |
| determine organisational politics, stakeholder incentives, strategic |
| importance, data quality, feasibility, risk appetite or other local  |
| facts without evidence.                                              |
|                                                                      |
| Include a section on evidence and confidence: how practitioners      |
| distinguish what is known, assumed, inferred and unknown; what forms |
| of evidence are more or less useful; how they seek disconfirming     |
| evidence; and how they decide which uncertainty to reduce next.      |
|                                                                      |
| Include a section on tensions and trade-offs rather than pretending  |
| every principle points in the same direction. Where there is no      |
| universal answer, explain how a strong practitioner reasons about    |
| the tension.                                                         |
|                                                                      |
| Finish with a clear description of what good professional judgement  |
| looks like in the final work product. Only after the substantive     |
| handbook is complete, add a short operational quick reference        |
| containing the most important diagnostic questions, warning signs    |
| and conditional rules for AI coaching.                               |
+----------------------------------------------------------------------+

# 10. Audit the codification

**When to use:** Use before treating a Professional Expertise Guide as
finished or uploading it as the canonical expertise file.

+----------------------------------------------------------------------+
| OUTPUT / HANDOFF                                                     |
|                                                                      |
| The strongest test is behavioural: would the guide cause the AI to   |
| ask better questions and challenge weak reasoning more               |
| intelligently?                                                       |
+----------------------------------------------------------------------+

+----------------------------------------------------------------------+
| COPY / PASTE PROMPT                                                  |
|                                                                      |
| Audit the attached Professional Expertise Guide as if it will be     |
| used as durable context by an AI system.                             |
|                                                                      |
| Do not judge it mainly on polish, length or how many frameworks it   |
| contains. Judge whether it genuinely codifies professional           |
| judgement.                                                           |
|                                                                      |
| Test the guide against the following questions:                      |
|                                                                      |
| \- Does it define the professional judgement clearly and distinguish |
| it from a broad topic?                                               |
|                                                                      |
| \- Does it explain how excellent practitioners reason, not merely    |
| what they know?                                                      |
|                                                                      |
| \- Are principles developed with rationale, conditional judgement,   |
| evidence, exceptions and consequences?                               |
|                                                                      |
| \- Does it contain real decision rules or only slogans?              |
|                                                                      |
| \- Does it explain what evidence should change confidence and what   |
| should be investigated next?                                         |
|                                                                      |
| \- Does it capture warning signs, failure patterns and novice        |
| mistakes?                                                            |
|                                                                      |
| \- Does it preserve meaningful trade-offs and genuine disagreement?  |
|                                                                      |
| \- Does it show weak versus strong reasoning and explain the         |
| difference?                                                          |
|                                                                      |
| \- Does it distinguish generalisable expertise from context that the |

|                                                                      |
| \- Would an AI using this guide ask materially better questions than |
| an AI given only a summary of the topic?                             |
|                                                                      |
| \- Is the main body written as professional expertise in coherent    |
| prose rather than as a compressed bullet list?                       |
|                                                                      |
| Identify where the document is only information about expertise      |

| trade-off or contextual nuance that should be added.                 |
|                                                                      |
| Finish with three outputs: (1) what is already strong; (2) the       |
| highest-priority gaps; and (3) a revised structure or section plan   |

| professional judgement.                                              |

|                                                                      |

| What Good Looks Like tells it the quality standard. The conversation |
